# OpenStaffs 运维参考

这份参考讲办公室的「基础设施」：文件在哪、各配置怎么写、改完怎么生效、出问题怎么查。日常协作与能力边界见 **openstaffs** 技能；只有涉及配置与运维时才需要读本参考。

> **总原则**：办公室的基础设施归属老板——全局配置、别人的人定义、部门声明、项目声明都由老板掌握。**权限规则不因运维而放宽**：你的可访问范围 = 各层 `permissions` 表（按工具 → 路径列表）累加 + 运行时自动授予（自己的工作目录对所有工具、主管对管理子树的写权）；超出范围时**向老板请求授权**（或由老板执行），不要硬来。
>
> 「老板」在本参考中同样指你的负责人（办公室所有者）：称谓可在全局配置里自定义（见下），以系统提示词与实际界面为准。

## 办公空间全景

```
<办公空间>/                       # 老板启动时指定的运行目录（与框架代码分离）
├─ agents/                       # 组织树：文件夹 = 部门（可任意嵌套），`<名字>.agent.config.json` = 人
│  ├─ department.config.json     # 根部门声明（可选：alias / head）
│  ├─ staff0.agent.config.json   # 0 号员工「首席管家」（首次启动自动创建；权限 = 空间根）
│  ├─ <名字>.agent.config.json   # 人（根部门直属；id = 文件名主干，全局唯一）
│  └─ <部门>/                     # 子部门（可再嵌套，任意深度）
│     ├─ department.config.json  # 部门声明（可选：alias / head）
│     └─ <名字>.agent.config.json
├─ projects/<项目 id>.project.config.json   # 项目 = 群聊（**扁平文件**：owner / members / 能力 / 权限）
├─ work/<名字>/                  # 各人的工作目录（会话 cwd、私聊会话链、memory/ 原生记忆）
└─ openstaffs/                   # 空间附属 + 机器私有（可见的部分可版本化、随空间整包迁移）
   ├─ space.config.json          # 空间声明（prompt / skills / mcp / permissions；首次启动写入空声明）
   ├─ skills/<技能名>/SKILL.md   # 共享技能库（各层 config 按名引用）
   ├─ mcps.json                  # MCP 全局定义（各层 config 按名引用）
   └─ .data/                     # 机器私有（gitignore；老板维护，你只读）
      ├─ config.json             # 全局配置：providers / model / thinkingLevel / memory / port / bossName / skillPaths / mcp
      ├─ chains/group-<项目>/<人>.md # 群会话链（机器维护；私聊链在 work/<人>/conversation_ids.md）
      ├─ state.json              # 老板的 pin 标记（机器维护，不要手改）
      ├─ permission-requests.json # 待处理授权请求（机器维护，处理完即删）
      ├─ messages.sqlite         # 消息真相库：房间消息流水（机器维护，不要手改）
      └─ state.sqlite            # 基座会话库：某条会话的原文与模型上下文（机器维护，不要手改）
```

> **搬到哪儿**：根下只有门面 `agents/`、`projects/`、`work/`、`openstaffs/` 四项。`AGENTS.md` / `profile.md` 作为能力载体已**退出运行时**（不再被读取）。

> **消息真相：自有库 `openstaffs/.data/messages.sqlite`**（`node:sqlite`，一条投递 = 一行、房间视图键为 `store:<seq>`）。
> 房间视图 / 历史 / pin 校验 / `room_history` 工具**全部查该库**；基座 `state.sqlite` 只用于「某条会话的原文」视图与模型上下文，
> **不再是消息真相**（一处发言只落一行，不需要读侧合并 / 去重）。

## 级别定义（系统 / 空间 / 项目 / 员工）

**级别是逻辑级别**——它回答「这是谁的内容、谁是权威方、改了影响谁」；文件夹只是它的落点。

| 级别 | 常用别名 | 是什么 | 逻辑上包含 | 权威方 | 改动代价 |
| --- | --- | --- | --- | --- | --- |
| 系统 | 框架、OpenStaffs 本体 | OpenStaffs 框架本身 | 内置模板、内置技能、内置工具 | 框架作者 | 改代码／升级框架 |
| 空间 | 办公空间、空间、办公室、运行实例 | 一个运行实例 + 指定的运行目录 | 该目录下全部 agents、projects 及其附属 | 老板 | 改文件即可 |
| 项目 | 群聊、群 | 空间内一个协作单位 | 项目成员 + 群声明（能力 / 权限） | 群成员 | 改文件即可 |
| 员工 | agent、职员、同事 | 空间内一个 Agent（人） | 人格 prompt / 部门归属 / 按工具权限 | 本人（写自己的工作目录）+老板 | 改文件即可 |

> 指根一律说「办公空间」；中间层一律说「项目（群聊）」；最上层的内置技能叫「系统内置技能」。别名只用于口语，文档正文一律用主名。

## 空间初始化与 0 号员工

- **目录已合并**：机器私有不再是独立隐藏目录，统一收在 `openstaffs/.data/`（含全局配置、pin 状态、授权请求、基座会话库、消息自有库）。`openstaffs/` 的其余内容（`space.config.json`、`skills/`、`mcps.json`）属空间资产，可版本化、随空间整包迁移。
- **新建空间**：启动时若没有 `openstaffs/space.config.json`，框架写入**空声明** `{}`（系统 prompt 由框架自持）。判断只看文件是否存在——已存在（含空文件 / 坏 JSON）一律不覆盖。
- **0 号员工（首席管家）**：首次启动若没有 `agents/staff0.agent.config.json`，框架自动创建。它对**空间根（整个办公空间）有写权限**（「空间级附属 = 老板地盘」的有意例外；配置里写作相对路径 `..`——P3 的权限路径相对配置文件所在目录 `agents/` 解析），直属老板；未配 `model` 时用全局默认。**它可创建 / 修改 agent 与项目定义**：写 `*.agent.config.json` 时是硬保护的唯一例外，但仍必须用 `write`、合法 JSON、且 `permissions` 通过 attenuation（授不出空间外权限）。
- **不做迁移**：旧版把机器私有放在空间根下的隐藏目录，那套位置**不再读取**（破坏性更新）；老板需要的话自行搬迁数据。

## 全局配置 `openstaffs/.data/config.json`

```json
{
  "providers": { "opencode-go": { "apiKey": "sk-…" } },
  "model": "opencode-go/deepseek-v4.1-flash",
  "thinkingLevel": "high",
  "port": 4319,
  "bossName": "老板",
  "skillPaths": ["~/global-skills"]
}
```

| 字段 | 说明 |
| --- | --- |
| `providers` | 供应商 → `{ apiKey }`。可用：`opencode-go` / `anthropic` / `openai` / `deepseek` / `google` / `openrouter`；写了名单外的供应商，启动会直接报错 |
| `model` | 全局默认模型 `供应商/模型 id`（第一个 `/` 前是供应商，模型 id 可再含 `/`）；人没配模型时兜底 |
| `thinkingLevel` | 可选：全局默认思考强度。**档位由模型决定**（候选 `off` / `minimal` / `low` / `medium` / `high` / `xhigh` / `max`）；配置端**不校验**。非思考模型（只支持 `off`）、未显式映射的 `xhigh` / `max`、非法档，界面都展示 `default`（= 未显式设定、走模型默认档）。优先级：人的 `<名字>.agent.config.json` > 本字段；改动**新开会话**生效（与 `model` 一样，建议重启后整体确认） |
| `memory` | 可选布尔，**常驻记忆总开关**（缺省 `true`）。`false` = 员工新会话不注入记忆、`memory_*` 工具不可用（数据保留）；员工层同名字段优先。直读配置文件——**注入看新开会话，工具调用即时生效**。细节见「记忆（原生能力）」 |
| `port` | 可选，默认 4319；优先级：启动参数 / `OPENSTAFFS_PORT` > 本字段 > 4319 |
| `bossName` | 可选：负责人称谓（缺省「老板」）。空值/缺失自动回落，**不可为空、不可移除**；界面、消息与工具文案统一消费此称谓。直读配置文件——刷新页面 / 新开会话即生效，无需重启 |
| `skillPaths` | 可选：外部技能目录数组（老板的全局技能库）。写法：`~/` 开头（或裸 `~`）= 家目录，绝对路径 = 原样，其余 = 相对办公空间根目录。算**空间级**技能，所有会话可用；改动**新开会话**生效。**只指向你自己信任的目录**——这里的技能会进入**所有**员工会话的制度提示词（`name` / `description` 注入，正文由员工按需 `read`）。 |

- **未配置模式**：`providers` 为空、或 `model` 缺失 / 格式非法 → 服务照常启动、页面显示引导页，但办公 API 被拒（除状态接口外返回 409）。这是「还没配好」，不是坏了。
- **进程级生效**：改完这份文件必须**重启服务**（老板在终端 Ctrl+C 后重新 `npm start`）。不重启会出现「部分生效」的假象——状态接口与新会话的模型名会提前变化，但供应商凭据还是启动时那份。**判断配置是否生效，一律以重启后为准**。
- 这份文件**含密钥**：你可以读取它来排查问题，但绝不在任何消息、文件里复述 / 复制 / 转发密钥内容。

## 统一配置 `*.config.json`

四类能力载体（空间 / 部门 / 项目 / 员工）**同一种形状**，共用一套解析器：

| 作用域 | 文件 |
| --- | --- |
| 系统 | 框架内置（`src/`），非用户可编辑 |
| 空间 | `openstaffs/space.config.json` |
| 部门 | `agents/<部门…>/department.config.json` |
| 项目 | `projects/<名字>.project.config.json`（扁平） |
| 员工 | `agents/<部门…>/<名字>.agent.config.json` |

字段（同一形状，按作用域取用）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `alias?` | string | 展示名（员工缺省 = 文件名主干；部门缺省 = 文件夹名、根部门缺省「办公室」；项目缺省 = 文件名主干） |
| `avatar?` | string | 头像路径（声明式字段，当前仅解析保留） |
| `prompt?` | string（内联） | 人格 / 职责 / 总纲，**随系统提示词注入**（不再有独立提示词文件） |
| `skills?` | string[] | 技能**名**（到 `openstaffs/skills/<名>/` 解析） |
| `mcp?` | string[] | MCP server **名**（到 `openstaffs/mcps.json` 解析） |
| `permissions?` | 按工具 → 路径列表 | 见「权限：按工具 → 路径」 |
| `model?` | `供应商/模型 id` | 覆盖全局默认模型（仅员工层有意义） |
| `thinkingLevel?` | string | 覆盖全局默认思考强度（仅员工层有意义） |
| `head?` | string[] | 部门负责人（只能写本级直属成员） |
| `owner?` | string[] | 群主名单（声明式字段，当前仅解析保留） |
| `members?` | string[] | 项目成员（只列员工；老板是天然成员） |

- 坏 JSON / 坏字段**安全降级**：缺文件 = 无此层；顶层非对象 = 视为无；单字段类型不对 → 记 issue 并跳过该字段（不崩）。
- 缺失的技能名 / MCP 名 → 跳过并记 `missing`，不影响建会话。

### 累加路线（一律累加，无覆盖 / 无优先级）

| 类别 | 累加路线 |
| --- | --- |
| `permissions`（**落盘**） | 项目 config + 员工 config 两层 |
| `permissions`（**运行时**，不落盘） | 各自的工作目录（所有工具）+ 主管对管理子树的写权 + 技能库（read） |
| `skills` / `mcp` | 空间 → 部门链（根 → 叶递归）→ 项目 → 员工 |
| `prompt` | 空间 → 部门链 → 项目 → 员工（换行拼接） |

### 权限默认值

- 新建员工 / 项目写入：`write: []`、`read: ["./"]`、`bash: ["./"]`；**未登记的工具默认空**。
- `permissions` 里的**相对路径相对该配置文件所在目录**解析（员工 config 的 `./` = 该员工所在部门目录；项目 config 的 `./` = `projects/`）。

## 人在哪：`agents/**/<名字>.agent.config.json`

**人 = 一个配置文件**：`agents/` 下（可嵌套的）部门目录里的 `<名字>.agent.config.json`；**文件名的骨干就是人 id**（**全局唯一**，重复时只保留先扫描到的那个）。**文件夹 = 部门**，可任意嵌套、深度不限。

人配置文件（`alias` / `prompt` / `skills` / `mcp` / `permissions` / `model` / `thinkingLevel` / `memory`）：

| 字段 | 说明 |
| --- | --- |
| `prompt` | **人格与职责**（`prompt` 字段，会话装配时注入 instructions；缺省空串）。改完**该人新开会话生效** |
| `alias` | 展示名（缺省 = 文件名主干）。改完**刷新页面即生效** |
| `model` | 覆盖全局默认模型 `供应商/模型 id`；引用的供应商要在全局配置里配好密钥。改完**该人新开会话生效** |
| `thinkingLevel` | 思考强度（可选，覆盖全局默认）。档位由模型决定，配置端不校验；非思考模型、未映射的 `xhigh` / `max` 与非法档在界面展示 `default`（= 未设定、走模型默认档）。改完**该人新开会话生效** |
| `memory` | 记忆开关（可选布尔）：覆盖空间默认。`false` = 该人不注入记忆、记忆工具不可用（数据保留）。注入改完**新开会话生效**；工具调用即时读 |
| `skills` | 技能**名**数组（累加路线的一环；解析到 `openstaffs/skills/<名>/`）。改完**该人新开会话生效** |
| `mcp` | MCP server **名**数组（累加路线的一环；解析到 `openstaffs/mcps.json`）。改完**该人新开会话生效** |
| `permissions` | 按工具 → 路径列表（见「权限：按工具 → 路径」）；**相对路径相对本文件所在目录**解析。每轮写校验即时读 |

部门声明 `agents/<部门…>/department.config.json`（可选：目录本身就是部门，声明只为展示名与负责人）：

| 字段 | 说明 |
| --- | --- |
| `alias` | 部门展示名（缺省 = 文件夹名；根部门缺省「办公室」）。改完刷新页面即生效 |
| `head` | **负责人名单**（字符串数组）：只能写**本级直属成员**的人 id；写子部门成员 / 写不存在的 id 一律**视为无** |

- **负责人（主管）与穿透管理权**：某部门的 `head` 就是该部门的主管；主管对**自己担任 head 的部门整棵子树**（部门目录 + 其中的人，任意深度）有**写权**与**管理权**，**同级兄弟部门不可写**。沿祖先链向上找最近的 `head` 即某人的管理者；全链都没有 = 直接归老板。
- **工作目录 `work/<名字>/`**：私聊与群聊的会话工作目录都落这里；私聊会话链（`conversation_ids.md`）也落这里（群聊链在机器私有区，见「项目」章节）；对**所有工具**开放。`memory/` 是该人的原生记忆目录，由 `memory_*` 工具维护（见「记忆（原生能力）」）。
- **人的 `permissions` 由授权流程改写**：**除空间管家 staff0 外，任何人（含主管、含自己）都不可写 `<名字>.agent.config.json`**（硬保护，防自授权）。授权弹框批准后由框架代写**发起者自己** agent config 的 `permissions[tool]`（不经过工具闸门）。**当前没有「主管直接写下级定义 / `permissions`」的通道**：人的定义只能由老板、staff0 或框架的授权流程写。staff0 的例外也只放行 `write`，仍需合法 JSON + attenuation。`department` / `space` / `project` 类 `*.config.json` 可用 **`write` 工具**写，但要求在该工具有效集内、JSON 合法、且 `permissions` 通过 attenuation（见「权限：按工具 → 路径」）；**bash 不得写配置**（见下）。
- id 里**不要含空白或 `@`**（与提及语法冲突，无法被定向），也不要 `__` 开头（保留给 boss / system）。`@` 提及永远用 id，alias 不参与识别。

## 项目 = 扁平配置 `projects/<id>.project.config.json`

项目**不再有目录**：一场群聊 = 一个声明文件 `projects/<id>.project.config.json`（文件名的骨干 = 项目 id）。

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `members` | ✓ | 成员名单（字符串数组）：只列**员工**（id = `<名字>.agent.config.json` 的文件名主干）；老板是每个群的天然成员，不用（也不建议）写进来。为空 → 群聊发送报「群还没有成员」 |
| `alias` | | 群展示名（缺省 = 文件名主干） |
| `owner` | | 群主名单（声明式字段，当前仅解析保留） |
| `prompt` | | 群级任务规范（群聊会话注入） |
| `skills` / `mcp` / `permissions` | | 该群的能力与权限（技能名 / server 名 / 按工具路径，见「统一配置」） |

- 群聊里每名成员各自一条会话链、相互不可见；链落 `openstaffs/.data/chains/group-<项目>/<人>.md`（机器维护）。要传递信息，写进各自工作目录的文件或发消息（见 openstaffs 技能）。
- `members` 里的 id 必须是某个人的 id（`<名字>.agent.config.json` 的文件名主干）；写错 / 写不存在的人 → 群聊发送会报「员工不存在」。
- 群成员回复开头的 `@成员 id` 会触发对方开工（与老板发送同规则）；没写 @ 开头的群回复在显示与待办口径上补当前称谓（缺省 `@老板`）、视为发给老板。
- 项目**没有共享工作目录**：每个人的会话 cwd 都是自己的 `work/<名字>/`。

## 会话与消息投递（界面行为）

- **「新开会话」是「下一条消息开启新会话」**：点按钮只置就绪态（按钮高亮 + 输入框上方提示），**不落盘、不建会话**；再点一次取消。真正建会话发生在**这条消息投递到员工的那一刻**——私聊 = 该员工，群聊 = 这条消息 @ 到的每个成员（各开一条）。
  - 好处：空点不产生空会话；排队中被撤回 / 中断，也不产生会话。
  - 就绪态只对下一条消息有效（发完即清）；换房间 / 离开房间也会清。
  - 员工侧 `new_session` 工具不受影响（仍是立即重开，下一轮起生效）。
- **会话信息条**：聊天标题下方显示当前房间各活跃会话**实际在用**的模型全值（`供应商/模型 id`）、思考强度、已用上下文 / 模型窗口与占比（如「12.8K / 128K，10%」）。
  - 口径 = 会话创建时的**快照**，不是 `config.json` 现值；改配置后要**新开会话**才变。
  - 思考强度按模型能力判定（pi-ai `getSupportedThinkingLevels`，由 `reasoning` + `thinkingLevelMap` 推出）：模型不支持的档（非思考模型只支持 `off`；`xhigh` / `max` 需显式映射）、以及不属于七档的非法值，接口值仍为 `null`（不回落成别的档、不把无效值原样显示），界面统一展示为 `default`。模型目录查不到时无法判定，按原值展示。
  - 上下文用量是**已提交上下文**的估算：新会话在首轮回复前可能显示 0，首轮后按模型回报更新；窗口占比按模型 `contextWindow` 计（实际压缩还会预留输出空间）。
- **排队中的消息可见、可单条撤回**：员工正在跑时，老板发的消息先落在**待发队列**（消息区里显示为灰／半透明的「排队中」气泡，标注等待的成员 + 「撤回」按钮），投递开始后原地变成正常气泡。
  - 消息的**真相在自有库**（`openstaffs/.data/messages.sqlite`）：老板发送即落库并广播（键 `store:<seq>`），刷新 / 重启后历史都在；「排队中」只是 UI 状态，进程内展示。
  - **撤回**（点「撤回」）= 撤掉这条消息里**还没开始**的投递，不投递给员工；已经开始投递的撤不回（撤不回时会提示「撤不回」），要停住正在跑的那是**「中断」**（房间级，同时停掉房间里所有在跑的成员）。
  - 同一次发送发给多个成员时按「消息」粒度合并成一条气泡：已经有成员收到（真气泡已出）就只在这条气泡上挂「排队中：<还没拿到的成员>」。
  - 排队态是**进程内**的展示：重启服务后仍在 Pi 待办里的输入照常投递，只是界面不再显示「排队中」。

## 并发与写冲突

- **并行粒度 = 关系**：同一员工每个关系（私聊、每个群各一条）一条独立会话；同一个群里 @ 他多次 → 同一条会话排队串行，不同房间 → 并行。发送队列的 key 是 `dm:<员工>` / `group:<项目>:<员工>`。
- **保护范围**：`<空间根>/work/**` 下的 `read` / `write` / `edit`。配置目录（`agents/` / `projects/`）不参与，仍由 JSON + attenuation 闸门保护；`bash` 不参与（命令行无法可靠解析目标文件）。
- **规则**：
  1. 写 `work/` 下**已存在**的文件前，本会话必须先 `read` 过它；没读过 → 拦下，提示“先 read”。
  2. 读过后文件版本（大小 + 内容 SHA-256）变了 → 拦下，提示“已被其他会话修改，请重新 read”。
  3. 新文件可以直接写；写成功后版本戳刷新，同一会话可继续编辑。
  4. 同一路径正在被另一条会话写时，后到的被拦（预留锁 60 秒过期，防中断导致的死锁）。
- **记忆不走这套**：`memory_*` 工具直接操作 `work/<id>/memory/`，内部同步 + 原子替换，天然安全；profile 是 last-writer-wins。
- **产物分目录（约定，不强制）**：私聊 `data/dm/`，群聊 `data/group-<项目 id>/`，减少并行会话的共享面。
- **只对单进程服务生效**：保护状态在内存里；同一办公空间跑多个服务实例不在保护范围内（正常部署只有一个 `npm start`）。

**排障**：

| 报错 / 现象 | 处理 |
| --- | --- |
| “写已有文件前请先用 read 读取它” | 先 `read` 目标文件，再写 |
| “文件已被其他会话修改，请重新 read” | 重新 `read`，基于最新内容改；不合并就写会覆盖对方 |
| “另一条会话正在写这个文件” | 稍后重试（预留锁最多 60 秒） |
| `bash` 改的文件拦不住 | 预期行为；共享文件统一走 `read` + `write` / `edit` |

## 会话详情（只读）与定义文件

**会话详情（只读）**

- 入口：聊天标题下方的**会话信息条**里，每条活跃会话后面的「详情」文字按钮。
- 进去就是**那一条会话**（不再有 Tab 切会话）：系统提示词（折叠）、完整模型上下文（用户 / 助手 / 工具调用 / 工具结果）、模型 / 思考强度 / 上下文用量、会话 id、cwd。
- 数据来源：`GET /api/employees/<id>/sessions/<convId>/context`；**只读，不触发模型**。
- 正文不自动替换（避免阅读位置跳动）：该会话有新消息 / 流式输出 / 工具活动时，顶部出现「有新内容」按钮，点它重取；「刷新」重取正文。
- 不做 Markdown 渲染（纯 `<pre>` + 折叠），定位是查阅 / 调试。

**定义文件（只读）**

- 入口：侧栏**每一行**（员工 / 部门 / 项目）右侧的 `{}` 按钮。
- 展示该层 `*.config.json` 的**原文**（纯 `<pre>`，不做解析、不做差量）：员工 = `agents/**/<id>.agent.config.json`，部门 = `agents/**/department.config.json`（根部门 = `agents/department.config.json`），项目 = `projects/<id>.project.config.json`。
- 数据来源：`GET /api/config?scope=agent|department|project&id=<员工 id / 部门路径 / 项目 id>`（部门路径空串 = 根部门）；只认这三类已知文件名，不存在 / 越界一律 404；该层没写文件时回 `text: null`（页面上提示「该层没有配置文件」）。
- 权限：与老板自己的文件权限一致（能看不能改）；写 `*.agent.config.json` 仍然只走 staff0 / 授权流程。

## 会话装配：系统段 + prompt 链 + 记忆 + 技能清单

- 会话创建时，框架把**四段**拼成系统提示词（instructions），此后随会话**固化**（快照）：
  1. **系统段**（框架自持）：`src/prompts/environment.md`（环境与通用规则）+ `src/prompts/dm.md` 或 `src/prompts/group.md`（会话前缀）。模板在 `npm start` 时读入内存；升级框架后**重启**，新开会话即用新版。
  2. **prompt 链**：各层 `*.config.json` 的 `prompt` 按**空间 → 部门链（根 → 叶）→ 项目（群聊）→ 员工**累加——空段丢弃、同值保留、`\n\n` 连接，**无覆盖 / 无优先级**。
  3. **记忆**：该人 `work/<id>/memory/` 的 profile 全文 + 未过期条目的索引（说明见 `src/prompts/memory.md`；关闭或两者都为空时不注入动态块，关闭时说明也不注入）。
  4. **技能清单**：本次会话可用的技能（见「技能」章节；恒含系统内置）。
- **系统 prompt 由框架自持**：四个模板在 `src/prompts/`，改工作区不会改系统文案。`space.config.json` 的 `prompt` 只是**可选的自定义层**（默认空），与部门 / 项目 / 员工 `prompt` 一起累加。
- **变量**（在任意层的 `prompt` 里写 `{{变量}}`；支持 `{{members.0.name}}` 这类多级路径；未知变量渲染为空串；数组用「、」连接，对象取 `name` 缺省 `id`）：

| 变量 | 含义 |
| --- | --- |
| `agent_name` / `agent_id` | 你的展示名 / 你的 id |
| `boss_name` | 负责人称谓（`bossName`） |
| `private_dir` | 私人目录（= 会话 cwd，私聊 / 群聊都 = `work/<你>`） |
| `project_name` / `project_id` | 项目展示名 / 项目 id（私聊为空） |
| `members` / `member_count` | 群成员数组（`{id,name}`）/ 成员数（私聊为空 / 0） |
| `session_kind` | 会话类型：`dm`（私聊）/ `group`（群聊） |
| `session_info` | 当前会话的一句话描述（私聊 = 「与『负责人称谓』的私聊」；群聊 = 项目展示名 + id + 成员名单） |

- 整套系统提示词在**会话创建时固化**（随会话快照）：要换系统模板 / prompt 链 / 记忆 / 技能清单，都需**重启后新开会话**（用户 `prompt` 改完新开会话即可）。

## 记忆（原生能力）

记忆是框架原生能力，不依赖外部服务。每个员工一份，落在自己的工作目录：

```
work/<id>/memory/
  profile.md        常驻记忆：每次新会话全文注入；纯 Markdown，≤ 8192 字节
  <id>.md           普通记忆：frontmatter（id / title / description / pinned / created / updated）+ 正文
  archive/<id>.md   memory_remove 的归档（框架不读；归档不占用 id）
  .state.json       新鲜度侧车（lastUsed；不要提交）
  .gitignore        首次写入时创建，忽略 .state.json
```

**开关**：空间 `config.json` 的 `memory`（缺省 `true`）+ 员工 `.agent.config.json` 的 `memory`（覆盖）。关闭 = 不注入、工具报「记忆未启用」，数据不删。

**注入**：会话创建时把 profile 全文 + 未过期条目的索引（id · 标题 — 简介，pinned 置顶）拼进 instructions，随快照固化。索引上限 40 条 / 16384 字节（pinned 不计入、不截断）；超出只影响注入，`memory_list` 仍可看全。标题 ≤ 40 字、简介 ≤ 80 字且必须**单行**（含换行 / 控制字符会被拒绝）。

**新鲜度与遗忘**：计时起点 = 最近取用 → 更新时间 → 创建时间。`memory_get` / `memory_add` / `memory_update` 会续期；`memory_list` 不续期。非 pinned 且 **90 天**未用 → 移出索引与默认列表（文件仍在：`memory_list(include_stale: true)` 可见，`memory_get` 取到即复活）。pinned 永不淘汰。

**工具**：`memory_list` / `memory_get` / `memory_add` / `memory_update` / `memory_remove` / `memory_profile`。只在 `work/<自己>/memory/` 内读写，不需要额外权限表。

**排障**：

| 现象 | 处理 |
| --- | --- |
| 新会话看不到记忆 | 检查开关（空间 / 员工）；检查 `memory/profile.md` 与条目文件是否存在且非空；开关改动要**新开会话** |
| 记忆不出现在索引 | 可能已过 90 天：`memory_list(include_stale: true)` 看，`memory_get` 取一次即复活；或 `memory_update` 续期 |
| 记忆工具报「记忆未启用」 | 员工或空间配置里 `memory` 为 `false` |
| 某个记忆读不到 | 文件 frontmatter 坏了（`memory_list` 会提示跳过的文件）：手工修正该文件的 `id` / `title` / `description`（必须单行），或删文件后用 `memory_add` 重加——坏文件对工具不可见，`memory_update` 改不了它 |
| 索引提示「还有 N 条未展示」 | 超过 40 条 / 16 KiB 上限：用 `memory_list` 查看，或合并 / 删除旧条目 |
| 误删 | `memory_remove` 是归档：到 `work/<id>/memory/archive/` 人工找回 |

- 不要直接改 `memory/*.md`（绕过续期会让索引失真）；内容修正一律走 `memory_update`。
- 删除是归档、不物理销毁；pinned 条目要先取消置顶再删。

## 技能（Agent Skills）

- 每个技能 = 一个含 `SKILL.md` 的目录；frontmatter 提供 `name`（缺省 = 目录名）与 `description`；正文由 agent 按需 `read`。
- 引用方式：各层 `*.config.json` 的 `skills` 数组写**技能名**，框架到 `openstaffs/skills/<技能名>/`（后备：老板配的外部技能库 `skillPaths`）解析并**累加**（空间 → 部门链 → 项目 → 员工）；写了不存在的名字会被**跳过**（不影响建会话）。
- **系统内置技能恒在**（框架 `src/skills/`）：无论各层怎么配，系统内置技能始终进入会话技能清单。
- 技能清单在会话创建时固化：新增 / 修改技能 → 新开会话生效；`SKILL.md` 正文改完即时生效（`read` 时才读）。
- 空间技能库 `openstaffs/skills/` 属老板地盘，你写不进去；技能一律通过各层 config 的 `skills` 名引用获得。

## 改动生效方式（只由 3 档机制决定，与文件放哪儿无关）

| 机制 | 何时生效 | 属于这档的东西 |
| --- | --- | --- |
| 启动初始化 | **重启服务** | `config.json` 的供应商 / 密钥 / 端口；MCP server 注册；系统 prompt 模板（`src/prompts/` 读入内存） |
| 会话装配（进 instructions，快照） | **新开会话** | 系统段（环境 + 私聊 / 群聊前缀）、prompt 链（空间 → 部门 → 项目 → 员工）、记忆（profile + 索引）、技能清单、MCP 选择、全局 / 人的 `model` 与 `thinkingLevel` |
| 运行中按需读取 | **即时** | `SKILL.md` 正文（`read` 时读）、各层 `*.config.json` 的 `permissions`（**每轮写校验即时读**）、项目 config 的 `members`（@ 路由与成员校验） |
| 直读展示 | **刷新页面** | `bossName`、人的 `alias`、部门 `alias` |

- **「快照」是刻意的**：保护供应商的 prompt cache，并让会话可复现——不是 bug。会话进行中改人的 `prompt` / 技能清单，老会话不会变。
- **别被假象骗到**：`config.json` 改全局 `model` 后，新开会话就会显示新模型名，但供应商凭据还是启动时那份 → **一律以重启后为准**。

## MCP（外部工具）

MCP server 是外部进程，通过 stdio 提供工具。**定义只有一份：`openstaffs/mcps.json`**；各层 `*.config.json` 用 `mcp: ["<server 名>"]` **按名引用**（空间 → 部门链 → 项目 → 员工累加）。

格式（顶层只能是 `mcpServers`）：

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "${config.mcp.github.token}" },
      "cwd": ".",
      "timeoutMs": 60000
    }
  }
}
```

- **server 名**就是 `mcpServers` 的 key，直接用于工具名、扩展名与凭据引用；只允许字母、数字、`_`、`-`（不能含点号或空白）。名字不合法会在启动日志里点名报错并跳过。
- 装配：按名解析后**累加**（空间 → 部门链 → 项目 → 员工）；写了未定义的名字会**跳过**（不影响建会话）。旧的多层 `mcp.json`（系统 `src/mcp.json` / 空间 / 项目 / 员工）**已全部退役**。
- 凭据：**不写明文**。密钥放 `openstaffs/.data/config.json` 的 `mcp.<server>.<key>`，`mcps.json` 只写 `${config.mcp.<server>.<key>}`。缺凭据时该 server 报错并跳过。**密钥优先放 `env`**：写进 `args` 会出现在进程参数里（`ps` 可见）。
- 生效：启动时连接并注册工具；新增 / 改 server 或工具要**重启**。某个 server 是否进入你的会话随会话装配——要**新开会话**。
- 工具名：`mcp__<server>__<tool>`。工具总数超过 20 时全部延迟加载，先用 `tool_search` 搜索再调用。
- 生命周期：启动并行连接（`initialize` + `tools/list` 各受 10s 连接超时约束）；30s 心跳，工具调用在途时跳过心跳；连续 2 次心跳失败才重连；崩溃按 1s、2s、4s… 退避重连，最多 5 次；服务退出时清理子进程。
- **员工不能自己挂 server**：需要新 server 请老板在 `openstaffs/mcps.json` 里定义，再在相应层的 `mcp` 字段里按名引用。带密钥的 server 仍需老板把凭据加进 `openstaffs/.data/config.json`。
- 排查：看服务端日志里的 `[mcp]` 行；坏 JSON、缺字段、缺凭据、连接失败都会点名具体文件 / server / 凭据键。

## 权限：按工具 → 路径

- **形态**：`permissions` 是**按工具分组**的对象，每个工具的值 = **路径列表**：

  ```json
  "permissions": { "write": ["./"], "read": ["./", "/tmp"], "bash": ["./"] }
  ```

- **工具**：目前 `write` / `read` / `bash`（`edit` 与 `write` 共用 `write` 表）；**未来新增文件系统工具同理**——未登记的工具默认空，不会继承别的工具的路径。
- **默认值**：新建员工 / 项目为 `write: []`、`read: ["./"]`、`bash: ["./"]`；未登记工具默认空。
- **相对路径**相对**该配置文件所在目录**解析（员工 config 的 `./` = 员工所在目录；项目 config 的 `./` = `projects/`）。
- **累加**：`permissions` 的落盘路线 = **项目 config + 员工 config**，两层**累加**（接受同值重复，无覆盖 / 无优先级）；空间 / 部门的 `permissions` 不进权限路线。
- **运行时额外授予**（不落盘、自动生效）：① 自己的工作目录 `work/<你>/` 对**所有工具**可用；② 主管对自己部门的**整棵子树**有 `write`（部门目录 + 其中的人；同级兄弟部门不可写）；③ 技能库根（空间技能 / 外部技能库 / 系统内置）对 `read` 开放——不给 read 开放技能库，`skills` 引用就不可用。
- **attenuation（写入校验）**：用 **`write` 工具**写任何 `*.config.json` 的 `permissions` 时，**每个工具的值必须 ⊆ 写者该工具的有效集**（逐级收窄：授 `/a` 可授 `/a/b`，授 `/a/b` 不可授 `/a`；空集恒合法；路径比较大小写敏感）。**全工具统一**，与工具语义无关——**不可提权授予他人**。**bash 写配置一律被拦**（无法做 JSON + attenuation 校验）：命令里出现任何配置文件名（`space` / `department` / `*.project` / `*.agent`，含裸相对文件名）都被拒绝，必须改用 `write` 工具。
- **硬保护**：**除空间管家 staff0 外，任何工具都写不了 `*.agent.config.json`**（含自己的）；staff0 也只能用 `write` 整体写。用 `edit` 改任何 `*.config.json` 一律被拦（引导改用 `write` 整体写入，以便校验 attenuation）。
- **config 写入流程**：用 `write` 写 `space` / `department` / `project` / `agent` 类 `*.config.json` 时，会额外要求「合法 JSON + 顶层对象」，并对内容里的 `permissions` 做 attenuation 校验。这是**在你自己有效集内**写配置的通道——**不是**「主管写下级定义」的通道：除 staff0 外，下级（及所有人）的 `*.agent.config.json` 属硬保护，本工具与方法都写不了。
- **人级授权**：员工超出有效集的路径用 `request_permission` 申请（可带 `tool`，缺省 `write`）→ 老板在弹框批准 → 框架把路径**追加进该员工 agent config 的 `permissions[tool]`**（不经过工具闸门）。也可由老板直接改配置。

## 运维操作与授权

**权限规则不因运维而放宽**——就是你手册里的那套。超出范围时按下面做：

**你直接能做**（有效集内）：

- 在自己的工作目录 `work/<你自己>/` 里创建 / 修改文件；
- 作为主管时，在自己管理的部门子树里创建 / 修改文件（部门目录 + 人，任意深度）；
- 在你各层 `permissions` 表放行的路径里操作（如你的 `write` 表里含的其它目录）。

> 你的展示名 / 模型 / 人格 / 权限（`alias` / `model` / `prompt` / `permissions`）都在自己的 `<名字>.agent.config.json` 里，**属受保护文件，除空间管家 staff0 外不可写**（主管也不能写）——这类改动请老板或 staff0 来做，或走 `request_permission`。

**超出有效集的运维操作**（建新员工 / 调整组织 / 建新项目 / 改全局配置 / 动别人的文件……）：

1. **把方案准备好**：步骤、内容草稿、涉及的确切路径——草稿能落在你工作目录的，先落盘；
2. **向老板请求授权**：用 `request_permission` 工具发起（可带 `tool`：`write` / `read` / `bash`；老板在界面的授权弹框中整体接受/拒绝；批准后框架把路径**追加进你 agent config 的 `permissions[tool]`** 并通知你）；也可以由老板直接改配置后完成；
3. 或者**由老板亲自执行**：你把步骤和内容交给老板操作。

授权示例——老板批准后，你的 `agents/eng/alice.agent.config.json` 里出现 `"permissions": { "write": ["../sales/"] }`，即放行 `agents/sales/` 整棵子树（相对**你配置文件所在目录** `agents/eng/` 解析）；只想放行同目录的某个文件，写 `["bob.agent.config.json"]` 即可。

> **不要用 `bash` 绕过权限**：`write` / `edit` / `read` 会被工具层拦截并拒绝；`bash` 对**普通路径**只做**近似**检查（`cd` + 相对裸文件名等仍可能绕过），靠你自觉；但**配置文件是 fail-closed**——命令里出现任何配置文件名（`space` / `department` / `*.project` / `*.agent`，含裸相对文件名）一律被拦，改配置只能走 `write` 工具。运维场景最容易诱惑越界，守住边界。

## 常见故障对照

| 现象 | 原因 / 处理 |
| --- | --- |
| 启动报「必须指定办公空间目录」 | 启动时漏了目录参数；目录也不能是框架目录本身 |
| 端口被占用 | 改全局 `config.json` 的 `port`（或启动参数）后重启 |
| 有员工回复失败（红色错误气泡） | 该员工 `model` 引用的供应商没配 `apiKey`，或模型写法有误；错误要等供应商重试 / 超时后才浮出，可能超过一分钟 |
| 改了 `config.json` 不生效 | 进程级配置：重启服务；以重启后为准 |
| 改了 `.agent.config.json` 不生效 | 会话创建时已固化：`prompt` / `model` / `thinkingLevel` 要**新开会话**生效；`alias` 是实时的，**刷新页面**即变 |
| 写文件 / 命令被拦「访问控制」 | 目标不在你该工具的有效集内（各层 `permissions` 累加 + 运行时授予）；用 `request_permission` 申请，或请老板改配置 |
| 写 `*.agent.config.json` 被拦 | 属预期：人的定义是**硬保护**（含自己的）；除 staff0 外请老板改，或走授权流程由框架代写 `permissions` |
| 写配置报「attenuation 校验失败」 | 你写 `permissions` 时授出了自己范围外的路径（**不可提权**）；收窄到你的有效集内再写 |
| 某人不见了 | 文件名不是 `<名字>.agent.config.json`（普通 `.json` / 别的后缀不算人）；或落在隐藏条目（`.` 开头）里；或该 id 与别人**重复**（全局唯一，只保留先扫描到的那个） |
| 改了人的 `prompt` / 技能没反应 | 会话创建时已固化：新开会话生效 |
| 展示名改了但界面没变 | `alias` 是实时的：刷新页面 |
| 消息显示「排队中」很久不动 | 目标员工在跑（一轮没结束）；可点该气泡的「撤回」撤掉它（撤不回时说明已经开始投递），或点「中断」停掉房间里所有在跑的成员 |
| 「撤回」提示撤不回 | 这条消息已经开始投递（员工已经拿到）——撤回只作用于**还没开始**的投递；要停正在跑的任务用「中断」 |
| 消息一直没回复 | 可能是被撤回（或随「中断」撤下）了；被撤回的消息不投递给员工，也不会进该会话的原文（但老板那条发言仍留在消息库 / 房间历史里，只是没人收到） |
| 「排队中」气泡撤掉了但消息还在 | 属预期：老板发送即落自有库（消息真相），撤回只撤掉**还没开始的投递**；排队标识消失、这条发言仍留在房间历史里 |
| 员工回复只出现在「会话原文 / 历史」、房间视图里看不到 | 该员工的会话**订阅失败**（坏链 / 建立订阅失败，日志有 `会话订阅失败（convId=…）`）：agent 回复靠 pump 订阅落库，没订阅就没有库行，而房间视图只读自有库（不做会话原文对账）→ 该条回复只在「某条会话的原文」视图可见，房间视图与之不一致属**已知取舍**。**重启服务**（`registerAll` 重新扫描订阅）即补齐订阅、后续回复恢复正常 |
| 点了「新开会话」但会话没换 | 属预期：该按钮只置「下一条消息开启新会话」，**发出一条消息**才真正建会话（空点不建、撤回也不建） |
| 群聊报「群还没有成员」 | 项目 config（`projects/<id>.project.config.json`）缺失或 `members` 为空 |
| 群聊报「消息需要 @ 至少一位群成员」 | 消息没 @ 到任何本群成员（不再广播、直接拒发）；在输入框上方勾选发送对象即可 |
| 群聊报「员工不存在: xxx」 | 项目 config 的 `members` 里的 id 不是任何人的 id（要用 `<名字>.agent.config.json` 的文件名主干，不是展示名） |
| `@` 没定向成功 | `@` 后必须写员工 id（`<名字>.agent.config.json` 的文件名主干），alias 不参与识别；`@` 名粘连标点（如 `@alice，`）不算命中；只 `@` 老板或 `@` 不存在的人都会被拒绝；只有消息**开头**的 @ 前缀块生效（正文中/尾的 `@` 只是文字，不触发） |
| 员工回复里的 `@` 没触发成员 | 同样只认**回复最开头**的 @ 前缀块；正文中/尾的 @ 是文字。开头 @ 了成员却没人开工 → 检查成员 id 拼写与项目 config 的 `members`；开头 @ 无效（写错 id / 标点粘连 / 只有 @ 没正文）时，该回复视为发给老板 |
| 侧栏红点不点亮 / 口径疑问 | 红点 = **老板自己 pin（图钉）的消息数**：鼠标移到气泡上点 📌 即计数、再点取消。打开房间、有人发言都**不会**自动清零；只看当前房间视图里的 pin，历史（已关闭）会话里的 pin 不计入 |
| 想清空上下文 | 别删目录：用「新开会话」或 `new_session` 工具；旧会话在「历史」里可回看 |
| 员工复读自己的消息（「收到（上面是我的原消息回显）」这类） | 旧版本 bug（员工主动发言曾以「用户消息」形态落盘）：升级后新发生的已杜绝；**旧会话里的历史条目仍会残留**这类形态——对该员工「新开会话」即净 |
| 点了授权弹框但员工没反应 | 通知消息投递失败（看服务端日志）；或该员工期间新开过会话——让他再尝试写入即可 |
| 授权弹框重启后还在 | 属预期：待处理请求落盘于 `openstaffs/.data/permission-requests.json`，处理完即删 |
