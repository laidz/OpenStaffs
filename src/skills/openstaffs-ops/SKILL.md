# OpenStaffs 运维参考

这份参考讲办公室的「基础设施」：文件在哪、各配置怎么写、改完怎么生效、出问题怎么查。日常协作与能力边界见 **openstaffs** 技能；只有涉及配置与运维时才需要读本参考。

> **总原则**：办公室的基础设施归属老板——`.openstaffs/` 全局配置、别人的档案、权限文件都由老板掌握。**写权限规则不因运维而放宽**：你只能写自己的目录、自己所在的项目目录、以及 `permission.json` 放行的路径；超出范围时**向老板请求授权**（或由老板执行），不要硬来。
>
> 「老板」在本参考中同样指你的负责人（办公室所有者）：称谓可在全局配置里自定义（见下），以环境段与实际界面为准。

## 办公空间全景

```
<办公空间>/                       # 老板启动时指定的运行目录（与框架代码分离）
├─ AGENTS.md                     # 空间总纲（可选；注入所有会话）
├─ agents/<员工 id>/             # 员工（目录名 = 员工 id，不可变）
├─ projects/<项目 id>/           # 项目 = 群聊（目录名 = 项目 id）
├─ openstaffs/                   # 老板的能力与附属（可见、可版本化、随空间整包迁移）
│  ├─ skills/<技能名>/SKILL.md   # 空间级技能：全部会话可见（同名时员工 / 项目技能更优先）
│  └─ mcp.json                   # 空间级 MCP server（见「MCP（外部工具）」）
└─ .openstaffs/                  # 机器私有（含密钥与运行状态；老板维护，你只读）
   ├─ config.json                # 全局配置：providers / model / thinkingLevel / port / bossName / skillPaths / mcp
   ├─ state.json                 # 老板的 pin 标记（机器维护，不要手改）
   ├─ permission-requests.json   # 待处理授权请求（机器维护，处理完即删）
   └─ state.sqlite               # 对话库（机器维护，不要手改）
```

## 级别定义（系统 / 空间 / 项目 / 员工）

**级别是逻辑级别**——它回答「这是谁的内容、谁是权威方、改了影响谁」；文件夹只是它的落点。

| 级别 | 常用别名 | 是什么 | 逻辑上包含 | 权威方 | 改动代价 |
| --- | --- | --- | --- | --- | --- |
| 系统 | 框架、OpenStaffs 本体 | OpenStaffs 框架本身 | 内置模板、内置技能、内置工具 | 框架作者 | 改代码／升级框架 |
| 空间 | 办公空间、空间、办公室、运行实例 | 一个运行实例 + 指定的运行目录 | 该目录下全部 agents、projects 及其附属 | 老板 | 改文件即可 |
| 项目 | 群聊、群 | 空间内一个协作单位 | 项目成员 + 共享工作区 | 群成员 | 改文件即可 |
| 员工 | agent、职员、同事 | 空间内一个 Agent | 人格／记忆／技能／权限 | 本人（+老板） | 改文件即可 |

> 指根一律说「办公空间」；中间层一律说「项目（群聊）」；最上层的内置技能叫「系统内置技能」。别名只用于口语，文档正文一律用主名。

## 全局配置 `.openstaffs/config.json`

```json
{
  "providers": { "opencode-go": { "apiKey": "sk-…" } },
  "model": "opencode-go/deepseek-v4.1-flash",
  "thinkingLevel": "high",
  "port": 4319,
  "bossName": "老板",
  "skillPaths": ["~/global-skills"]
}
```

| 字段 | 说明 |
| --- | --- |
| `providers` | 供应商 → `{ apiKey }`。可用：`opencode-go` / `anthropic` / `openai` / `deepseek` / `google` / `openrouter`；写了名单外的供应商，启动会直接报错 |
| `model` | 全局默认模型 `供应商/模型 id`（第一个 `/` 前是供应商，模型 id 可再含 `/`）；员工没配模型时兜底 |
| `thinkingLevel` | 可选：全局默认思考强度。**档位由模型决定**（候选 `off` / `minimal` / `low` / `medium` / `high` / `xhigh` / `max`）；配置端**不校验**。非思考模型（只支持 `off`）、未显式映射的 `xhigh` / `max`、非法档，界面都展示 `null`。优先级：员工 `config.json` > 本字段；改动**新开会话**生效（与 `model` 一样，建议重启后整体确认） |
| `port` | 可选，默认 4319；优先级：启动参数 / `OPENSTAFFS_PORT` > 本字段 > 4319 |
| `bossName` | 可选：负责人称谓（缺省「老板」）。空值/缺失自动回落，**不可为空、不可移除**；界面、消息与工具文案统一消费此称谓。直读配置文件——刷新页面 / 新开会话即生效，无需重启 |
| `skillPaths` | 可选：外部技能目录数组（老板的全局技能库）。写法：`~/` 开头（或裸 `~`）= 家目录，绝对路径 = 原样，其余 = 相对办公空间根目录。算**空间级**技能，所有会话可用；改动**新开会话**生效。**只指向你自己信任的目录**——这里的技能会进入**所有**员工会话的制度提示词（`name` / `description` 注入，正文由员工按需 `read`）。 |

- **未配置模式**：`providers` 为空、或 `model` 缺失 / 格式非法 → 服务照常启动、页面显示引导页，但办公 API 被拒（除状态接口外返回 409）。这是「还没配好」，不是坏了。
- **进程级生效**：改完这份文件必须**重启服务**（老板在终端 Ctrl+C 后重新 `npm start`）。不重启会出现「部分生效」的假象——状态接口与新会话的模型名会提前变化，但供应商凭据还是启动时那份。**判断配置是否生效，一律以重启后为准**。
- 这份文件**含密钥**：你可以读取它来排查问题，但绝不在任何消息、文件里复述 / 复制 / 转发密钥内容。

## 员工目录 `agents/<id>/`

| 文件 | 必需 | 说明 |
| --- | --- | --- |
| `AGENTS.md` | ✓ | 入口：人格与职责 |
| `profile.md` | | 岗位 / 职责 / 人格（与 AGENTS.md、MEMORY.md 一起注入 instructions） |
| `MEMORY.md` | | 长期记忆；**可变**（增 / 改 / 删），并要求保持精简——每次新开会话时**全量自动注入** |
| `config.json` | | 展示名 / 模型覆盖（见下） |
| `permission.json` | | 额外写权限：JSON 字符串数组；相对路径相对该文件所在目录。老板维护、你不可改写；**经授权弹框批准后由框架代写**（追加发起者申请通过的路径） |
| `skills/<技能名>/SKILL.md` | | 员工技能（Agent Skills 标准） |

员工 `config.json`（全部字段可选；文件损坏时按缺省处理，不影响出勤）：

| 字段 | 说明 |
| --- | --- |
| `alias` | 展示名（缺省 = 目录名）。改完**刷新页面即生效** |
| `model` | 覆盖全局默认模型 `供应商/模型 id`；引用的供应商要在全局配置里配好密钥。改完**该员工新开会话生效** |
| `thinkingLevel` | 思考强度（可选，覆盖全局默认）。档位由模型决定，配置端不校验；非思考模型、未映射的 `xhigh` / `max` 与非法档在界面展示 `null`。改完**该员工新开会话生效** |

> 目录名（id）不可变；展示名才是 alias。`@` 提及永远用 id；id 里不要含空白或 `@`（与提及语法冲突，无法被定向）。

## 项目目录 `projects/<id>/`

| 文件 / 目录 | 必需 | 说明 |
| --- | --- | --- |
| `members.md` | ✓ | 成员名单：每行一个成员 id（`- alice`、`* alice`、`alice` 都行；`#` 开头的行是注释）。**只列员工**；老板是每个群的天然成员，不用（也不建议）写进来 |
| `AGENTS.md` | | 项目级任务规范（群聊会话注入） |
| `project.json` | | `{ "alias": "展示名" }`（缺省 = 目录名） |
| `skills/<技能名>/SKILL.md` | | 项目技能：该群**全体成员**可见，同名时优先于员工技能 |
| `permission.json` | | 项目级额外写权限 |
| `data/` | | 共享工作区（约定：产物放这里） |
| `conversation_ids/` | | 会话链（机器维护） |

- 群聊里每名成员各自一条会话链、相互不可见；要传递信息，写进工作区文件或发消息（见 openstaffs 技能）。
- `members.md` 里的 id 必须是某个员工目录名；写错 / 写不存在的人 → 群聊发送会报「员工不存在」。
- 群成员回复开头的 `@成员 id` 会触发对方开工（与老板发送同规则）；没写 @ 开头的群回复在显示与待办口径上补当前称谓（缺省 `@老板`）、视为发给老板。

## 会话与消息投递（界面行为）

- **「新开会话」是「下一条消息开启新会话」**：点按钮只置就绪态（按钮高亮 + 输入框上方提示），**不落盘、不建会话**；再点一次取消。真正建会话发生在**这条消息投递到员工的那一刻**——私聊 = 该员工，群聊 = 这条消息 @ 到的每个成员（各开一条）。
  - 好处：空点不产生空会话；排队中被撤回 / 中断，也不产生会话。
  - 就绪态只对下一条消息有效（发完即清）；换房间 / 离开房间也会清。
  - 员工侧 `new_session` 工具不受影响（仍是立即重开，下一轮起生效）。
- **会话信息条**：聊天标题下方显示当前房间各活跃会话**实际在用**的模型全值（`供应商/模型 id`）、思考强度、已用上下文 / 模型窗口与占比（如「12.8K / 128K，10%」）。
  - 口径 = 会话创建时的**快照**，不是 `config.json` 现值；改配置后要**新开会话**才变。
  - 思考强度按模型能力判定（pi-ai `getSupportedThinkingLevels`，由 `reasoning` + `thinkingLevelMap` 推出）：模型不支持的档（非思考模型只支持 `off`；`xhigh` / `max` 需显式映射）、以及不属于七档的非法值，一律展示 `null`——不回落成别的档，也不把无效值原样显示。模型目录查不到时无法判定，按原值展示。
  - 上下文用量是**已提交上下文**的估算：新会话在首轮回复前可能显示 0，首轮后按模型回报更新；窗口占比按模型 `contextWindow` 计（实际压缩还会预留输出空间）。
- **排队中的消息可见、可单条撤回**：员工正在跑时，老板发的消息先落在**待发队列**（消息区里显示为灰／半透明的「排队中」气泡，标注等待的成员 + 「撤回」按钮），投递开始后原地变成正常气泡。
  - **撤回**（点「撤回」）= 撤掉这条消息里**还没开始**的投递，不投递给员工；已经开始投递的撤不回（撤不回时会提示「撤不回」），要停住正在跑的那是**「中断」**（房间级，同时停掉房间里所有在跑的成员）。
  - 同一次发送发给多个成员时按「消息」粒度合并成一条气泡：已经有成员收到（真气泡已出）就只在这条气泡上挂「排队中：<还没拿到的成员>」。
  - 排队态是**进程内**的展示：重启服务后仍在 Pi 待办里的输入照常投递，只是界面不再显示「排队中」。

## 环境段与模板

- 会话创建时，框架把「环境段」注入 instructions 最前：你的身份、当前会话、工作目录（群聊再加成员）。**环境段给出的事实优先相信**。
- 模板：**只有系统内置一份**——`src/prompts/dm.md`（私聊）/ `group.md`（群聊），空间不可覆盖。要加规矩写空间 `AGENTS.md`（追加注入、排在环境段之后）；要改环境段本身属**系统级**（改框架代码）。
- 变量（模板里写 `{{变量}}`，支持 `{{members.0.name}}` 这类多级路径；未知变量渲染为空串；数组用「、」连接，对象取 `name` 缺省 `id`）：

| 变量 | 含义 |
| --- | --- |
| `agent_name` / `agent_id` | 你的展示名 / 你的 id |
| `boss_name` | 负责人称谓（`bossName`） |
| `workdir` | 会话工作目录（私聊 = 你的目录；群聊 = 项目目录） |
| `project_name` / `project_id` | 项目展示名 / 项目 id（私聊为空） |
| `members` / `member_count` | 群成员数组（`{id,name}`）/ 成员数 |

- 环境段在会话创建时**固化**（随会话快照）：要换环境段，需**新开会话**；环境段本身属**系统级**——改它等于改框架代码（`src/prompts/`），不是空间可调的输入。

## 技能（Agent Skills）

- 每个技能 = 一个含 `SKILL.md` 的目录；frontmatter 提供 `name`（缺省 = 目录名）与 `description`；正文由 agent 按需 `read`。
- 来源与优先级（同名时越窄越优先）：**项目技能 → 员工技能 → 空间技能（`openstaffs/skills/` → `config.skillPaths` 的外部技能库）→ 系统内置技能**。
- 技能清单在会话创建时固化：新增 / 修改技能 → 新开会话生效；`SKILL.md` 正文改完即时生效（`read` 时才读）。
- 你可以给自己建技能：写 `agents/<你>/skills/<技能名>/SKILL.md`（在自己的写权限内）。空间技能（`openstaffs/skills/`）属老板地盘，你写不进去。

## 改动生效方式（只由 3 档机制决定，与文件放哪儿无关）

| 机制 | 何时生效 | 属于这档的东西 |
| --- | --- | --- |
| 启动初始化 | **重启服务** | `config.json` 的供应商 / 密钥 / 端口；MCP server 注册 |
| 会话装配（进 instructions，快照） | **新开会话** | 环境段模板、空间 / 项目 / 员工 `AGENTS.md`、`profile.md`、`MEMORY.md`、技能清单、全局 / 员工 `model` 与 `thinkingLevel` |
| 运行中按需读取 | **即时** | `SKILL.md` 正文（`read` 时读）、`permission.json`（每次写校验）、`members.md`（@ 路由与成员校验） |
| 直读展示 | **刷新页面** | `bossName`、员工 `alias` |

- **「快照」是刻意的**：保护供应商的 prompt cache，并让会话可复现——不是 bug。会话进行中改档案 / 技能清单，老会话不会变。
- **别被假象骗到**：`config.json` 改全局 `model` 后，新开会话就会显示新模型名，但供应商凭据还是启动时那份 → **一律以重启后为准**。

## MCP（外部工具）

MCP server 是外部进程，通过 stdio 提供工具。四层各一个 `mcp.json`：

| 级别 | 文件 |
| --- | --- |
| 系统 | `src/mcp.json`（框架自带空模板） |
| 空间 | `openstaffs/mcp.json` |
| 项目 | `projects/{项目}/mcp.json` |
| 员工 | `agents/{员工}/mcp.json` |

格式（顶层只能是 `mcpServers`）：

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "${config.mcp.github.token}" },
      "cwd": ".",
      "timeoutMs": 60000
    }
  }
}
```

- **server 名**就是 `mcpServers` 的 key，直接用于工具名、扩展名与凭据引用；只允许字母、数字、`_`、`-`（不能含点号或空白）。名字不合法会在启动日志里点名报错并跳过。
- 合并：系统 → 空间 → 员工 → 项目，同名**窄者胜**；不同名都挂。私聊没有项目层。
- 凭据：**不写明文**。密钥放 `.openstaffs/config.json` 的 `mcp.<server>.<key>`，`mcp.json` 只写 `${config.mcp.<server>.<key>}`。缺凭据时该 server 报错并跳过，不回落到宽层。**密钥优先放 `env`**：写进 `args` 会出现在进程参数里（`ps` 可见）。
- 生效：启动时连接并注册工具；新增 / 改 server 或工具要**重启**。某层是否生效随会话装配——要**新开会话**。
- 工具名：`mcp__<server>__<tool>`。工具总数超过 20 时全部延迟加载，先用 `tool_search` 搜索再调用。
- 生命周期：启动并行连接（`initialize` + `tools/list` 各受 10s 连接超时约束）；30s 心跳，工具调用在途时跳过心跳；连续 2 次心跳失败才重连；崩溃按 1s、2s、4s… 退避重连，最多 5 次；服务退出时清理子进程。
- 员工可以自己写 `agents/{员工}/mcp.json` 挂 server；这等于允许启动本地任意进程。只挂你信任的 server；带密钥的 server 仍需老板把凭据加进 `config.json`。
- 排查：看服务端日志里的 `[mcp]` 行；坏 JSON、缺字段、缺凭据、连接失败都会点名具体文件 / server / 凭据键。

## 运维操作与授权

**写权限规则不因运维而放宽**——就是你手册里的那套。超出范围时按下面做：

**你直接能做**（写权限内）：

- 改自己的展示名 / 模型：编辑自己目录的 `config.json`；
- 更新自己的档案 / 记忆 / 技能；
- 在所在项目里创建 / 修改文件（`AGENTS.md`、`data/`、`skills/` 等）。

**超出写权限的运维操作**（建新员工 / 建新项目 / 改全局配置 / 动别人的文件……）：

1. **把方案准备好**：步骤、内容草稿、涉及的确切路径——草稿能落在你目录或项目目录的，先落盘；
2. **向老板请求授权**：用 `request_permission` 工具发起（老板在界面的授权弹框中整体接受/拒绝；批准后框架把路径写入你的 `permission.json` 并通知你）；也可以由老板手工把路径写进 `permission.json`（员工级或项目级）后直接完成；
3. 或者**由老板亲自执行**：你把步骤和内容交给老板操作。

授权示例——老板在 `agents/alice/permission.json` 里写 `["../bob/"]`，即放行 `agents/bob/` 整棵子树（相对本文件所在目录解析）。

> **不要用 `bash` 绕过写权限**：`write` / `edit` 会被工具层硬件拦截并拒绝，`bash` 不受拦截——这里靠的是你自觉。运维场景最容易诱惑越界，守住边界。

## 常见故障对照

| 现象 | 原因 / 处理 |
| --- | --- |
| 启动报「必须指定办公空间目录」 | 启动时漏了目录参数；目录也不能是框架目录本身 |
| 端口被占用 | 改全局 `config.json` 的 `port`（或启动参数）后重启 |
| 有员工回复失败（红色错误气泡） | 该员工 `model` 引用的供应商没配 `apiKey`，或模型写法有误；错误要等供应商重试 / 超时后才浮出，可能超过一分钟 |
| 改了 `config.json` 不生效 | 进程级配置：重启服务；以重启后为准 |
| 改了档案 / 技能 / 记忆没反应 | 会话创建时已固化：新开会话生效 |
| 展示名改了但界面没变 | `alias` 是实时的：刷新页面 |
| 消息显示「排队中」很久不动 | 目标员工在跑（一轮没结束）；可点该气泡的「撤回」撤掉它（撤不回时说明已经开始投递），或点「中断」停掉房间里所有在跑的成员 |
| 「撤回」提示撤不回 | 这条消息已经开始投递（员工已经拿到）——撤回只作用于**还没开始**的投递；要停正在跑的任务用「中断」 |
| 消息消失了 / 一直没回复 | 可能是被撤回（或随「中断」撤下）了；被撤回的消息不投递给员工，也不会进 transcript |
| 点了「新开会话」但会话没换 | 属预期：该按钮只置「下一条消息开启新会话」，**发出一条消息**才真正建会话（空点不建、撤回也不建） |
| 群聊报「群还没有成员」 | `members.md` 缺失 / 为空 / 只有注释 |
| 群聊报「消息需要 @ 至少一位群成员」 | 消息没 @ 到任何本群成员（不再广播、直接拒发）；在输入框上方勾选发送对象即可 |
| 群聊报「员工不存在: xxx」 | `members.md` 里的 id 不是任何员工目录名（要用目录名，不是展示名） |
| `@` 没定向成功 | `@` 后必须写员工 id（目录名），alias 不参与识别；`@` 名粘连标点（如 `@alice，`）不算命中；只 `@` 老板或 `@` 不存在的人都会被拒绝；只有消息**开头**的 @ 前缀块生效（正文中/尾的 `@` 只是文字，不触发） |
| 员工回复里的 `@` 没触发成员 | 同样只认**回复最开头**的 @ 前缀块；正文中/尾的 @ 是文字。开头 @ 了成员却没人开工 → 检查成员 id 拼写与 `members.md`；开头 @ 无效（写错 id / 标点粘连 / 只有 @ 没正文）时，该回复视为发给老板 |
| 侧栏红点不点亮 / 口径疑问 | 红点 = **老板自己 pin（图钉）的消息数**：鼠标移到气泡上点 📌 即计数、再点取消。打开房间、有人发言都**不会**自动清零；只看当前房间视图里的 pin，历史（已关闭）会话里的 pin 不计入 |
| 想清空上下文 | 别删目录：用「新开会话」或 `new_session` 工具；旧会话在「历史」里可回看 |
| 员工复读自己的消息（「收到（上面是我的原消息回显）」这类） | 旧版本 bug（员工主动发言曾以「用户消息」形态落盘）：升级后新发生的已杜绝；**旧会话里的历史条目仍会残留**这类形态——对该员工「新开会话」即净 |
| 点了授权弹框但员工没反应 | 通知消息投递失败（看服务端日志）；或该员工期间新开过会话——让他再尝试写入即可 |
| 授权弹框重启后还在 | 属预期：待处理请求落盘于 `.openstaffs/permission-requests.json`，处理完即删 |
