## 演进路线图

产品开发遵循三步走，从「核心闭环」到「体验打磨」，最终走向「商业变现」。

### 🟢 第 1 期：核心引擎跑起来（MVP）

**目标：** 跑通「组织（文件夹）+ 协作（消息 / SQLite）」的产品逻辑，让老板能和第一个员工顺利对话。

1. **极简工作台 UI**：左侧员工 / 项目列表，右侧聊天主窗口；纯 Web、本地浏览器访问、无云端账号。
2. **「0 号员工」入职（首席管家 Staff0）**：内置唯一初始员工，通过自然语言对话引导老板完成系统配置（如填入 LLM API Key）。*约束：没有 API Key 就无法使用 LLM，引导本身存在冷启动难题。*
3. **职场 IM 与记忆闭环**：私聊（单方任务）与群聊（多方任务）；勾选员工（即以 `@员工` 写进消息）触发，每条消息都有明确对象（无「不 @ 即广播」）；消息流水入 SQLite（按时间段与关键字查询）；老板给消息加图钉（pin）即计入侧栏红点，作为「待办 / 稍后再看」的提醒（打开房间不自动清除；气泡工具栏另提供复制 Markdown 原文）。
4. **灵魂与记忆的可视化读取**：在 UI 点员工头像即可查看 / 编辑其人格与记忆文件，也可为该员工创建或挂载技能。

### 🟡 第 2 期：产品化与深度拟人

**目标：** 从「能对话的工具」升级为「能干活的团队」。

1. **技能插拔机制（SKILLS + MCP 双生态）**：员工挂载 SKILLS 能力包（已落地）与 MCP Servers（连接数据库、API、邮件等外部系统）；UI 展示「能力雷达图 / 技能证书」。
2. **自主驱动工作流（Inner Loop）**：员工拆解目标、自主推进；系统定时节拍器自动推进下一步，无需老板每次催促。
3. **员工交叉审计（Peer Review）**：A 产出 → 自动唤醒 B 质检 → A 修正；老板只管验收最终成果。
4. **记忆压缩与自动进化**：对话达到一定长度后，自动总结经验、更新记忆库并向老板汇报。

### 🔴 第 3 期：生态、盈利与人才市场

**目标：** 打造 AI 时代的「人才招聘平台」，通过闭源云端服务商业变现。

1. **云端「人才市场」（闭源商业版块）**：内置 SaaS 招聘中心；预配置好特定技能 / 性格的「高级 AI 员工」按「雇佣金」（买断 / 订阅）出售。
2. **丝滑的「入职体验」（0 号员工的高光时刻）**：招募后人才文件夹下载至本地；管家自动检查环境、安装依赖、以对话形式索要授权，完成新员工激活。
3. **三方创作者生态**：玩家打包售卖自己调教好的员工文件夹（自带人格 / 记忆 / 技能 / MCP），平台抽成。

## 核心壁垒

- **数据主权**：所有核心资产（业务文档、员工记忆）100% 存在本地 Markdown，直击注重隐私的极客与中小微企业主。
- **零学习成本**：抛弃节点连线与晦涩编排，回归「文件夹管理」与「IM 群聊」的直觉。
- **交互与状态分离**：协作走消息（SQLite）、状态走文件（Markdown / JSON）；多方协作以**扁平声明文件** `projects/<名字>.project.config.json`（`members` + `owner` + 能力 / 权限）落地，从结构上消除覆盖与数据污染。
- **人即配置、部门即文件夹（自包含）**：一个人 = 一个 `agents/**/<名字>.agent.config.json`（人格 `prompt` / 模型 / 展示名 / 技能索引 / 按工具权限），文件夹层级即部门组织；整棵组织树可版本化、下载即招募。
- **无限扩展的生命力**：人才市场 + SKILLS / MCP 双生态让主程序保持轻量，能力边界随招募无限拓展。

## 空间层命名与落点（已定稿）

四类能力载体（空间 / 部门 / 项目 / 员工）**同一种形状**（`*.config.json`），能力字段 `prompt` / `skills` / `mcp` / `permissions` 一律**累加**：

| 级别 | 别名 | 落点（prompt / skills / MCP） |
| --- | --- | --- |
| 系统 | 框架、OpenStaffs 本体 | 框架内置（`src/prompts/space.md`——唯一内置 prompt，新建空间时**物化**进 `space.config.json`；`src/skills/`），非用户可编辑 |
| 空间 | 办公空间、空间、办公室、运行实例 | `openstaffs/space.config.json`：`prompt` / `skills` / `mcp` / `permissions` |
| 部门 | 部门、团队 | `agents/**/department.config.json`：`alias` / `head` / `prompt` / `skills` / `mcp` |
| 项目 | 群聊、群 | `projects/<名字>.project.config.json`：`alias` / `members` / `owner` / `prompt` / `skills` / `mcp` / `permissions` |
| 员工 | agent、职员、同事 | `agents/**/<名字>.agent.config.json`：`alias` / `prompt` / `skills` / `mcp` / `permissions` / `model` / `thinkingLevel` |

- 管理辅助：`prompt` / `skills` / `mcp` = **累加**（空间 → 部门链 → 项目 → 员工，无覆盖 / 无优先级）；`permissions`（落盘）= **累加**（仅项目 + 员工两层），运行时另**自动授予**工作目录（所有工具）与主管对管理子树的写权。
- 技能按**名**引用 `openstaffs/skills/<技能名>/`（后备 `config.json` 的 `skillPaths` 外部技能库；系统内置技能恒在）；MCP 定义收敛为**全局单份** `openstaffs/mcps.json`，各层用 `mcp` 字段按名引用。
- 空间附属统一收在 `openstaffs/`（`space.config.json`、`skills/`、`mcps.json`；可版本化、随空间整包迁移）；机器私有（密钥配置与运行状态）收在其下的 `openstaffs/.data/`。
- 旧的格式分叉（`AGENTS.md` / `profile.md` / 四层 `mcp.json` / `permission.json` / `members.md`）在 P3 **全部退出运行时**；四类 `*.config.json` 同构、同一套解析器。
