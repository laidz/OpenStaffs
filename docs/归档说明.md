# 归档说明（2026-10-28）

OpenStaffs 于 2026-10-28 **归档（不再开发）**。仓库照常可读、可跑、可 fork，但不再接受新功能。

- 起点：2026-03-02；历史共 124 个提交，其中会议层的 20 个已 squash 为 1 条（归档时 `master` 上 106 个）。
- 最后一个功能提交：会议层成为一等公民 + 流式退化护栏。
- 标签：`v0.1.0-archive`。
- 可带走的资产：[`portable/`](../portable/README.md)。

## 为什么停

**一句话：目标变了。** 最初要解决的是"我自己几个项目的管理 + agent 工程化"，做到后期变成了
"维护一套 agent 运行时基建"——而这块正在被大厂免费化。

具体三条：

1. **坑的性质变了**。早期是产品坑（组织怎么表达、群聊怎么触发），后期全是基建坑
   （流式事件、abort、会话恢复、MCP 心跳超时、SSE 事件名对齐）。基建坑的边际收益极低：
   修完只让"能跑"变成"能稳定跑"，不产生新能力。
2. **赛道被免费接管**。2026 年 Claude Code Agent Teams、Codex 云端并行、Antigravity 2.0 的
   Agent Manager 都上线了。一个人和三家实验室的基建赛跑，赛道选错了。
3. **真实需求其实更小**。复盘下来真正需要的只有三件：多项目并行推进、agent 不越权、
   汇报能收敛。这三件用现有平台 + 一份协议文档就能覆盖，不需要自建运行时。

## 做成了什么（留下的结论）

- **组织 = 文件系统**：文件夹是部门、一个配置文件是一个员工、部门声明在同级。组织图不用画，`git` 就是变更史。
- **权限 = 工具 × 路径**：按工具配路径表、两层累加、私人目录与主管子树运行时授予、`*.agent.config.json` 硬保护（防自授权）、越权走异步申请。
- **会议 = 会话容器**；每个成员一条独立会话；会议不"结束"，随时可继续聊；"新建会议"只置就绪态。
- **群聊协议**：`@` 只在开头生效、多任务拆条、派活自报身份、谁拉起谁汇报、协作过程不 @ 老板、两三轮不收敛就停。这些规则都是从真实翻车里长出来的。
- **模型退化护栏**：流式阶段识别重复循环并中止，落库阶段兜底丢弃（prompt 约束不了，必须运行时兜）。

## 没做成什么

- Staff0 引导配置（冷启动）、消息全文/时间段查询、员工档案 UI 编辑、能力雷达图。
- 自主推进（Inner Loop）、员工交叉审计（Peer Review）、记忆压缩与自动进化。
- 云端人才市场 / 员工包交易——第 3 期的商业设想，未开工。
