# 手动验收清单

> 原载于 README（2026-10 迁出）；按顺序做一遍即可覆盖主要功能。随功能演进而更新。

1. **未配置启动**：项目目录里不建 `.openstaffs/config.json` → `npm start -- <项目目录>` → 浏览器打开首页显示引导页（工作区根、config 路径、示例 JSON）；`curl http://localhost:4319/api/status` 里 `configured` 为 `false`、`root` 等于你指定的项目目录，其它 `/api/*` 返回 409。不带目录参数直接 `npm start` → 报错退出并提示用法。
2. **配置生效**：按 README 写好 `config.json` → 重启服务 → 引导页消失；没有员工时左侧显示「还没有员工：在 agents/ 下创建目录并写 AGENTS.md」。
3. **建员工**：创建 `agents/alice/AGENTS.md`（可加 `config.json` 设 alias）→ 刷新页面 → 左侧出现该员工（设了 alias 就显示 alias，如「爱丽丝」）。
4. **私聊对话**：进入 alice 的私聊发一条 → 看到流式回复；不等它答完立刻再发一条，前一条继续生成且不阻塞后一条。
5. **建项目**：创建 `projects/demo/members.md`（含 alice）→ 刷新 → 左侧项目区出现 demo。
6. **群聊勾选定向（不再广播）**：群聊输入框上方罗列成员复选框——不勾选时发送按钮禁用、Enter 也发不出（正文里手动删光 `@` 同样禁用）；勾选 alice 后正文出现 `@alice`，发送后只有 alice 回复（其余成员无动作）；多选则各自回复；发送成功后勾选与 `@` 前缀保留，可直接发下一条——但只有 `@` 前缀、没有正文时仍发不出（发完直接按 Enter 不会连发空消息）；正文中/尾手写的 `@alice` 只是文字、不触发任何人（只有开头的 @ 前缀块生效）；消息记录（房间视图与员工 `room_history`）里 `@alice` 原样可见；只 `@老板` 或 `@不存在的人` 不算有效对象（界面禁用，直接调 API 会被 400 拒绝）。
7. **未读红点（待办口径）**：私聊里员工回复 → 红点；群聊里员工**发给老板**的消息（`@老板` 开头；没写 @、或开头 @ 无效的回复，也由系统视为发给老板）→ 红点；只 @ 其他成员的互聊消息不点红点（打开房间仍可见）；打开房间红点消失；切走、再发 → 红点再现。
8. **新开会话与历史**：点「新开会话」→ 当前视线清空；点「历史」能看到旧会话并只读回看。
9. **快照语义**：改 `agents/alice/profile.md` → 当前会话的回复不受影响；新开会话后再发消息 → 新档案生效。
10. **密钥不外泄**：任何 API 响应都不含 `apiKey`；`/api/status` 只含 `configured` / `root` / `port` / `model` / `providers`（供应商名单）/ `bossName`。
11. **多供应商**：`providers` 里配两家（如 opencode-go 与 anthropic）→ 给 alice 的 `config.json` 写 `"model": "anthropic/…"` → 刷新页面；alice 的会话用 anthropic，其他员工仍用全局默认模型。
12. **技能注入**：员工 / 项目 `skills/` 里的技能出现在新会话的技能清单（同名时项目技能优先；改后新开会话生效）；默认会话同时列出 `openstaffs` 与 `openstaffs-ops` 两个内置技能（位置分别指向 `src/skills/openstaffs/SKILL.md`、`src/skills/openstaffs-ops/SKILL.md`）。
13. **员工间 @ 触发与历史整洁**：群里让 alice 与 bob 协作——alice 的回复以 `@bob …` 开头 → bob 被触发并开工（房间视图里 alice 的消息只有一条、无重复气泡）；bob 回复没写 @ → 房间里显示为 `@老板 …` 且该房间红点 +1；员工 `room_history`（与历史回看）里每条消息都「谁发的、发给谁」清晰可读。
14. **Markdown 渲染**：让 alice 回复一条含 Markdown 语法的消息（加粗 / 列表 / 代码块 / 表格）→ 气泡内正确排版、链接可点；你自己发一条带 Markdown 语法的消息 → 保持字面原样（所见即所发）；员工输出里的原始 HTML（如 `<script>`）以文本显示、不执行。
15. **主动发言无回显**：私聊里让 alice 用 `send_message`（target=boss）汇报一条 → 房间里出现该消息，alice **不会**把它当新输入再回复（「收到（上面是我的原消息回显）」这类怪话不再出现）。注：升级前的旧会话里可能残留历史形态的条目，员工看到旧消息像自己发过的回显——「新开会话」即净（详见 openstaffs-ops 技能「常见故障对照」）。
16. **授权弹框（接受）**：私聊让 alice 尝试写工作区外的路径（如 `/tmp/openstaffs-demo/x.md`）→ 被拦且提示可申请；alice 调 `request_permission`（带理由）→ 右下角出现卡片（发起人 / 理由 / 绝对路径）；点「接受」→ `agents/alice/permission.json` 出现该路径、alice 收到「已完成授权」并继续写入成功。
17. **授权弹框（拒绝）**：再申请一次 → 点「拒绝」→ 无文件写入；alice 收到「已拒绝授权」；再次写仍被拦。
18. **群里多弹框**：两名成员分别申请 → 两张卡片堆叠、各自处理；批准消息以 `@<该成员> 已完成授权` 开头出现在群里、只触发该成员。
19. **重启保留**：申请后不处理 → 重启服务 → 刷新页面 → 卡片仍在，可正常处理。
20. **称谓自定义**：`config` 写 `"bossName": "掌柜"` → `bossName` 直读配置——**刷新页面 / 新开会话即生效（无需重启）**；界面发言人名 / 环境段 / 工具返回文案显示「掌柜」（**授权卡片本身不展示称谓**）；成员回复 `@掌柜` 计入待办红点；`@老板` 仍有效；`bossName` 置空 → 回落「老板」。
21. **异步认知**：观察 alice 发起申请后的行为：不反复尝试写入、不重复发起；等待期间继续做其他工作或结束本轮；批准后以新一轮继续。
